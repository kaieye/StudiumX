# 可操作的采纳建议与优先级排序

> **本文档目的**：将前 3 份对比文档的发现转化为具体的、可排期的采纳建议。
>
> **关键原则**：
> - 每条建议标注**优先级**（P0/P1/P2/P3）、**实现难度**、**预估工作量**
> - 每条建议标注与 StudiumX 产品地板的**兼容性**（不违反 ADR/SECURITY/TOOL_CONTRACT）
> - 每条建议标注**与现有代码的关系**（复用/新增/改造）

---

## 优先级定义

| 级别 | 含义 | 行动 |
|---|---|---|
| **P0** | 差距极大、影响基本产品专业性 | 立即排期 |
| **P1** | 差距较大、显著提升用户体验 | 近期排期 |
| **P2** | 差距中等、锦上添花 | 规划中排期 |
| **P3** | 差距小、可选借鉴 | 按需 |

## P0 建议（立即排期）

### P0-1. 国际化文案覆盖扩展

| 项 | 值 |
|---|---|
| **差距** | 45 条 → 目标 500+ 条（70 倍差距） |
| **实现方式** | 提取硬编码字符串 + 扩充 i18n JSON |
| **工作量** | 中（3-5 天，主要为提取和翻译） |
| **兼容性** | ✅ 完全兼容，无安全/架构冲突 |
| **现有基础** | `src/renderer/src/i18n/` + i18next 已搭建 |

**具体步骤**：
1. 安装 `i18next-scanner` 或使用 AST 工具扫描所有硬编码中文字符串
2. 将扫描结果转为 i18n key，填充 `en-US.json` 和 `zh-CN.json`
3. 添加 `check:i18n-coverage` 脚本检测未提取的硬编码字符串
4. 优先覆盖：侧边栏导航、设置面板、思维导图面板、工作台、对话框

**参考 Xmind**：`translation.json` 的 3167 条文案分类覆盖所有 UI 表面。

---

### P0-2. 快捷键面板

| 项 | 值 |
|---|---|
| **差距** | 无快捷键面板 vs 可搜索快捷键列表 |
| **实现方式** | 全局快捷键注册表 + 搜索面板 UI |
| **工作量** | 中（3-4 天） |
| **兼容性** | ✅ 完全兼容 |
| **现有基础** | `mind-map-keyboard.ts`、`mind-map-keyboard-navigation.ts` |

**具体步骤**：
1. 建立全局快捷键注册表（`useShortcutRegistry` hook）
2. 所有快捷键注册到中心化注册表（含描述、分类、当前绑定）
3. 创建 `ShortcutPanel.tsx` 组件（搜索 + 分类展示）
4. 绑定 `Cmd+/` 或 `Cmd+Shift+/` 唤起面板
5. 后续可增加自定义功能（P2）

**参考 Xmind**：`dialog-keyassist.html` - 可搜索快捷键列表 + 自定义 + 冲突检测。

### P0-3. 文件类型注册

| 项 | 值 |
|---|---|
| **差距** | 无 OS 级文件类型注册 vs 9 种文件类型 |
| **实现方式** | electron-builder fileAssociations + Info.plist |
| **工作量** | 低（1-2 天） |
| **兼容性** | ✅ 完全兼容 |
| **现有基础** | `build/` 目录已有打包配置 |

**具体步骤**：
1. 在 `electron-builder` 配置中添加 `fileAssociations`
2. 注册 `.md` / `.markdown` 为关联文件（Viewer 角色）
3. 设计并注册文件图标
4. 处理 `open-file` 事件（通过 `app.on('open-file')` 或 `second-instance`）
5. 后续注册 `.studiumx` 工作区文件类型

**参考 Xmind**：`Info.plist` 中的 `CFBundleDocumentTypes` + `UTExportedTypeDeclarations`。

### P0-4. AI 智能配色

| 项 | 值 |
|---|---|
| **差距** | 无 AI 配色 vs Smart Color Theme |
| **实现方式** | AI 根据思维导图内容语义生成配色方案 |

**具体步骤**：

4. 应用到 `MindMapTheme` 并实时预览
5. 在 `MindMapAiPanel` 中增加"智能配色"按钮

**参考 Xmind**：`dialog-smart-color-theme.html` + `dialog-smart-color-theme.js`。

## P1 建议（近期排期）

### P1-1. 思维导图高级元素：外框 + 概要

|---|---|

3. 在右键菜单中增加"添加外框"/"添加概要"操作
4. 更新 `xmind-compatibility.ts`：从 `dropped` 改为 `preserved`
5. 增加主题样式支持（`boundary` 和 `summary` 样式属性）

**参考 Xmind**：主题 JSON 中 `boundary` 和 `summary` 的完整样式定义。

## 不建议借鉴的方面

| 方面 | 原因 |
|---|---|
| 多窗口架构 | SPA 更适合教学对话连续工作流；内存更低 |
| 自研 UIKit | Tailwind 生态更好；维护成本更低 |
| 付费墙系统 | StudiumX 是 AGPL 开源，不需要 |
| 云端协作 | 与本地优先理念冲突；Web 适配层已覆盖远程能力 |
| 遥测上传 | 违反产品地板（无自动 remote telemetry） |
| MindManager/FreeMind 导入 | 小众格式，ROI 低 |
| 团队空间 | 与单人教学定位不符 |

## 与产品地板的兼容性检查

| 建议 | 影响产品地板？ | 检查结果 |
|---|---|---|
| i18n 扩展 | ✗ | 纯 UI 层，无安全影响 |
| 快捷键面板 | ✗ | 纯 UI 层 |
| 文件类型注册 | ✗ | OS 集成，不涉及教学 authority |
| AI 智能配色 | ✗ | 利用现有 AI 能力，通过 effect lattice |
| 外框/概要 | ✗ | v2 模型已预留，不破坏 settlement |
| timeline 布局 | ✗ | 纯渲染层 |
| PDF 导出 | ✗ | 不涉及工具执行或写入 |
| URL Scheme | ✗ | 需确保深链接不绕过审批策略 |
| 首次引导 | ✗ | 纯 UI 层 |
| 增加语言 | ✗ | 纯文案层 |

> **结论**：所有建议均与 StudiumX 产品地板兼容，不违反任何 ADR、SECURITY.md
> 或 TOOL_CONTRACT.md 约束。URL Scheme 需特别注意深链接不绕过审批策略。
