## 分阶段迁移细节（历史）

### Phase 0 — Design gate 冻结（文档 only）

- [x] 本 ADR 标记 Proposed → Accepted（gate open）/ 已实施分 phase
- [x] `docs/adr/README.md` 增加「平台能力分层 / Windows memory」索引行
- [x] 明确**不**打开：shell、YOLO、Windows strict CAS、destructive memory migration、MCP marketplace

### Phase 1 — Capability registry + 聊天热路径合同化

- 代码触点：`platform-capability-registry.ts`（纯解析 + 平台探测）、`teaching-conversation-runtime.ts`（`loadTeachingMemoryCatalogForTurn` 只读 registry；保留 degrade）、`memory-tools.ts`（按 capability 决定注册 write/read tools）、doctor / diagnostics 投影（脱敏）。
- 行为：win32 + memory `chat_hot_path_read` → `available: true, profile: windows_…` 或过渡期 `degraded_empty`，但不得抛 descriptor 异常；`NativeContainedDurableReplaceUnavailableError` 不得逃出 conversation turn 边界。

### Phase 2 — Memory catalog：Windows direct-path profile

- 2A 读路径：`list` / index scan / recall discovery 走 direct-path list+read；symlink/root 检查对齐 `workspace-path-target`。
- 2B 写路径：create/update/delete 走 direct-path create/overwrite；结果码对齐 P8 稳定集合子集。
- 2C 工具与 consent：memory tools 仅在 write capability `available` 时注册；consent 写同样受 profile 约束。
- 2D UI / i18n：Settings / doctor 显示「Windows：有限持久化（direct-path，非 descriptor）」。
- 实现约束：优先 peel 新模块（`windows-direct-path-memory-catalog.ts`）；与 `windows-direct-path-workspace-write.ts` 共享 path containment 原语；POSIX 路径保持 descriptor；`process.platform` 分支只在 registry / factory；fail-closed 保留场景：路径逃逸、非 regular 目标、不确定 publish → 稳定 error，不 retry 删文件。
- 数据迁移：不自动改写已有 memory 文件格式；legacy flat → scoped 仍只读 preflight（ADR-0006/0038）；Windows 首次可用时能读既有 JSON 则读，不能证明安全则 recovery issue，不静默丢弃用户可见数据。

### Phase 3 — 其余 descriptor consumer 清点与分类接线

定位仍绑定 descriptor 原语的 call site：

```sh
rg -n "openContainedRootDirectory|replaceAtContainedDirectory|NativeContainedDurableReplace" src/
```

每项 consumer 迁移仍遵守 ADR-0004：**未审查不自动挂新 profile**。验收：doctor 输出完整 consumer 表；unit 保证 chat 路径无 descriptor throw。

### Phase 4 — Provider / 空流与平台错误 UX 收口

- 确认 `invocation.ts` 空 SSE → JSON fallback 保留；与 ADR-0057 loop retry 不双计费混乱（文档化 attempt 边界）。
- `classifyProviderRecovery` 的 `empty_stream` 与 `unsupported_platform` **分轴**（后者不是 provider error）。
- renderer `operationFeedback`：平台 degrade 用独立 i18n key。

### Phase 5 — 文档、doctor、发布证明与 close-out

- [x] 更新 `SECURITY.md` 一句：Windows memory/workspace 为 layered non-CAS，非 OS sandbox 宣称
- [x] 更新 ADR-0004 / 0006「后果」交叉链接到本 ADR（不改写其历史 evidence 段落）
- [x] `pnpm doctor -- --json` 含 profile 字段（`scripts/lib/doctor-snapshot.mjs` → `platformCapabilities`）
- [x] Windows memory 可用证据：`teaching-memory-catalog-windows-direct-path.unit.test.ts` + `teaching-ipc-gateway` Windows memory 路径（host win32 unit）
- [x] 本 ADR 状态 → 已实施（分 phase 勾选）；outcome/audit Windows 仍 unavailable

**明确永不在本 ADR close-out 内：** Windows strict descriptor/CAS；YOLO / danger-full-access / 默认 shell；destructive memory migration；跨文件 transaction；远程 telemetry。

## 一句话决策摘要

> **学 Codex：平台能力分层、显式较弱 Windows profile、热路径可降级；不学 Codex：danger-full-access / 默认 shell；不学“假 CAS”。**
> 迁移顺序：**registry 合同化 → Windows memory 读 → 写 → 其它 consumer 分类 → UX/doctor 诚实收口**；每步独立 PR，权威写路径永不静默假成功。
